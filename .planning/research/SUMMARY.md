### Features & Scope (MEDIUM — cross-checked census of 15+ products)

- **Table stakes (v1):** one-script-tag floating launcher; one-click screenshot attached to the report; annotation set **pen / arrow / rectangle / text / destructive mask / undo**; console errors+warnings for bugs, optional logs for plain feedback; env metadata (URL path, browser, OS, viewport, timestamp); bug-vs-feedback type; **Pending / In Progress / Resolved + reopen**; list+filter+sort; detail view of screenshot/logs/metadata; delete report / erase identity; multi-project with per-project public write-only key; `docker-compose up` self-hosting; one-snippet install; en/es. **MEDIUM** (census: Usersnap ships 5 tools, Sentry 2+undo, BugPin 5 — the common denominator is exactly this set).
- **Destructive masking is *ahead of the category*** — every competitor blurs/overlays (Marker.io, Usersnap, Sentry, Toado, BugPin); only Instabug blacks out natively before the file exists. Irreversible masking costs zero extra bytes and is positioning gold. **MEDIUM**.
- **Capture evidence (Q-06):** the market converged on server-side re-render (Marker.io default, Usersnap prerender) or native `getDisplayMedia` — **nobody leads with DOM serialization**, independently confirming D-08. Marker.io's documented re-render failure list (cross-origin iframes, Shadow DOM, canvas/WebGL, video, CSP) is D-08 verbatim. Server-side rendering is closed on privacy grounds (page URLs to a renderer service; no container for it under INV-03). **MEDIUM** (Sentry's internal mechanism **UNVERIFIED**).
- **Triage:** 3 states is at the category floor, not below it (Marker.io ran Open/Resolved/Archived for years). Reopen is universal and near-free. Assignee is a deliberate cut under R-05 single-admin. **MEDIUM**.
- **Defer to v2:** crop (1/8 products), step numbering (0/8), full-page capture, network logs (needs URL-stripping + schema change), duplicate-prevention pins (needs a public read API — security-sensitive), word-overlap "similar reports" hint (no-AI heuristic — allowed later), comments/notes, labels, per-project analytics, CSS-selector capture, key-rotation UI (confirms Q-04's v2 lean). **Exception:** the offline-queue differentiator is **partially pulled into v1** by the H-9 correction below (durability queue); full offline UX stays v2.
- Anti-feature boundary holds (no third-party integrations, no session replay/video, no AI analysis, no gamification/auto-fix, no managed SaaS/payments, no third-party OAuth2/SSO, no multi-user accounts, no unit-test suites). **Do not cite "BugMoo" (does not exist — LOW/not found) or DebugMe (deadpooled — LOW, third-party listings only) in the TFG memoria.**

### Architecture (MEDIUM-HIGH; structure = reasoning on decided constraints)

- **R-02's 8 ports stand as decided**; one refinement: 6 are client-side (`CaptureSource`, `Redactor`, `Enricher`, `Annotator`, `Transport`, `WidgetHost`) and 2 server-side (`Storage`, `AuthProvider`). `packages/contracts` is a leaf holding **data shapes only**. No 9th port: `Clock` / `Logger` / `IdGenerator` are interface ceremony (examined and rejected). `WidgetHost` and `CaptureSource` earn port status on real dual implementations.
- **Redaction ordering is the safety-critical invariant (Q-04):** **T1** auto-redact on `ImageData` at capture, *before the editor ever displays the image*; **T2** user masks baked destructively into the working bitmap at stroke completion; **T3** at export: flatten annotations → **re-bake all masks as the last pixel operation** → re-run auto rules → fresh `toBlob`. With this order an annotation stroke physically cannot leak masked pixels. **MEDIUM** (redaction-failure literature, 4+ independent sources incl. news-grade incidents).
- `CaptureSource.capture(): Promise<ImageData>` returns **raw `ImageData` on purpose** — a Blob-returning port would let unmasked encoded bytes exist before `Redactor` runs. Structural SEC-02. Ports are type-only (0 client bytes).
- **Transport is two-lane:** plain `fetch` with `Idempotency-Key` + bounded backoff retry while the tab is alive, plus an **IndexedDB durability queue flushed on `pageshow`** with the same idempotency key (server: `UNIQUE (project_id, idempotency_key)` with replay). `keepalive`/`sendBeacon` are demoted to ≤60 KB metadata-only flush / ≤1 KB receipts. **Spec-level (treat HIGH).**
- Ingest: `multipart/form-data` (`meta` JSON + `image` Blob) — never base64 (+33 % wire size, burns the 64 KiB budget a third faster). Edge order: rate limit → CORS allowlist → body/part caps → Zod → project-key lookup (write-only) → sanitize → `Storage.put` (server-generated UUIDv4 key, `projectId/<xx>/<uuid>.<ext>`, tmp→fsync→rename) → row. Structured 401/413/429/400.
- **Blob serving is the R-04 critical control:** DB-lookup-only key resolution (the request never names a file) + `^[a-z0-9]{2}\/[a-f0-9-]{36}\.(webp|png)$` + `path.resolve` prefix assertion + `nosniff` + `CSP: default-src 'none'; sandbox` + `CORP: same-origin` + allowlisted content-type + `Content-Disposition: attachment`. Volume mounted **only** in `api` — enforce with a CI compose assertion.
- **Hostile-host defence set (H-2/H-3):** inline `!important` on the host element (outranks document `!important`); host appended as last child of `document.documentElement`; `:host { all: initial }` first, then explicit re-declaration of every needed property; px-only (zero `rem`); zero `part=`/`::theme`; `--wb-`-prefixed custom properties declared locally; `<style>` inside the shadow root (not `adoptedStyleSheets`); `SHADOW_MODE=open` build with a module-scoped root registry so Playwright can pierce closed roots. **MEDIUM** (MDN/web.dev primaries; belt-and-braces set still needs one hostile-fixture spike).
- **Build order:** contracts → ingest slice → minimal SDK tracer bullet → editor (lazy) → enrichers → auth/triage → edge hardening → deploy closeout. **Two architecture-loaded decisions must be right at first build** — `WidgetHost` isolation strategy (Phase 3) and redaction ordering (Phases 3–4). Everything else is additive.

### Safety & Security (CRITICAL — these drive the roadmap; see Hard Constraints)

- **C-1 (CRITICAL — privacy; MEDIUM conf: 1 academic + 3 public tools):** Pixelated **and blurred** text is recoverable near-perfectly at typical UI font sizes (11–16 px) — Shacham et al. HMM recovery, Bishop Fox **Unredacter**, **Depix**, Positive Security **Underactor** + video averaging. An 8 px block still carries per-glyph stroke energy; partial blocks at the region edge leak a distinct averaging window (the exact artifact used to break the Unredacter challenge); α<255 is an overlay, not a redaction. **Only flat opaque fill (`ImageData`, α=255) is safe as the automatic primitive.**
- **C-2 (CRITICAL — defeats SEC-02 entirely; LOW–MEDIUM: reasoned + editor-pattern consensus):** Unmasked originals survive into exports via undo stacks (each undo entry *is* a full unmasked copy), layer-stack flattening, offscreen base buffers and stroke-over-mask z-order bugs. Required architecture: **one flattened working bitmap**, masks destructive and **not undoable** (explicit confirm), annotations flattened onto the *already-masked* bitmap, and **one `toBlob` sink** (`encodeFinal()` — grep gate: `toBlob|toDataURL|convertToBlob` appears exactly once in the SDK).
- **C-3 (CRITICAL — stored XSS in the admin's authenticated session; MEDIUM):** Attack surface = every user string (title, note, console messages, URL, user fields) **and the image bytes** (SVG is an active text format magic-byte sniffers misclassify; polyglot GIF/HTML executes on content-sniffing). Primary control = output encoding (React text nodes; zero `dangerouslySetInnerHTML`); ingest sanitisation is defence in depth. Image allowlist `image/webp`/`image/png` verified by magic bytes; **SVG rejected unconditionally**; re-encode on ingest where feasible (kills polyglots/EXIF/trailing payloads); hostile fixtures (`"><img src=x onerror=…>`, `javascript:`, BOM'd strings, polyglot GIF) in the e2e set **from day one**.
- **C-4 (CRITICAL — arbitrary file read; MEDIUM):** Path traversal on the blob volume. Client input never becomes a path component (the port's signature can't express it); DB-lookup-only serving; regex + resolved-prefix assertion (covers `..%5c`, NUL, Windows drive-relative tricks); unknown keys → **404**; volume in `api` only + CI compose assertion.
- **C-5 (CRITICAL — SEC-03 by payload instead of by header; LOW–MEDIUM):** Console logs carry tokens, serialized errors drag `Request` headers, `document.referrer`/hash state leak URLs. Controls: **closed payload schema (no free-form bag)**, CI grep gate for `document.cookie|localStorage|sessionStorage|Authorization|Bearer |credentials:` in `packages/sdk`, secret scrubber on serialized strings at push time (JWT-shape, `Bearer`, `key=`, Luhn-shaped card runs), never send `document.referrer` (origin at most).
- **H-9 (HIGH; spec-level = effectively HIGH):** `fetch keepalive` (in-flight body sum) and `sendBeacon` (queued) are **capped at 64 KiB**; a 60–150 KB screenshot is rejected outright on the unload path. **H-5 (HIGH; MEDIUM):** Safari/iOS canvas-area cap **16,777,216 px** silently yields blank captures (`getImageData` throws `InvalidStateError` on an allocated-but-unusable canvas); also total-canvas-memory kills *the host's* canvases. **H-1 (HIGH; LOW–MEDIUM):** masks stored in CSS/preview space misregister 2–15 px at HiDPI/zoom — enough to leave the first/last character of a secret visible.
- **H-6/H-7/H-8 (HIGH; MEDIUM):** console capture needs a re-entrancy guard + eager serialization + bounded ring buffer (patched `console` recursion freezes tabs); per-IP rate limiting alone is insufficient (spoofable `X-Forwarded-For` without explicit `trustProxy`, payload/decode bombs, multipart bombs, disk exhaustion) — layered caps needed; CSP/ad-blockers/service workers kill a third-party script silently — first-party delivery (self-hosted = our model) is the primary mitigation, neutral paths (`/api/incidents`, `/w.js`), fail loudly.
- **M-1 (MEDIUM → HIGH with real data):** The screenshot and console logs are themselves personal data; purging `user.*` does **not** anonymise the report. Retention must cover artifacts; erasure must delete `Storage` blobs (and the backup story documented); the purge must be an evidenced job (`purge_runs`); integration docs need an Art. 13 notice snippet + Art. 28 DPA template. **Not legal advice — flag to the supervisor before any compliance claim.** (SEC-03's "never read host cookies" does double duty under ePrivacy — keep it absolute.)
- **M-4/M-3/M-5/M-6 (MEDIUM):** `Secure` cookies are silently dropped on plain-HTTP demos (needs a documented TLS story / loud dev flag); `toBlob('image/webp')` **silently returns PNG** — detect via `blob.type` content sniff at startup and cover with a Playwright WebKit project; DOM-derived capture taints canvases and `getImageData` throws at send time (1×1 taint probe + file-attach fallback); closed roots need `Watchbug.version` + `diagnostics()` + a visible error state for operability.

## Conflicts & Reconciliations

### Conflict 1 — console / payload caps (three incompatible constant sets)

- **FEATURES position:** 50 console entries × 2 KB/message, 8 KB/stack, **100 KB total payload**, 10 MB image, 20 req/min per IP (market-tested values from feedback-hub/Feedex). *MEDIUM.*
- **PITFALLS position:** 200-entry drop-oldest ring buffer, 2,048 chars/message, 1,024 chars/arg, depth 3, cycle-safe, 64 KB total buffer; separate threat-driven body caps (5 MB body, 4 MB file, 25 MP decode guard) and layered rate limits. *MEDIUM.*
- **ARCHITECTURE position:** 100 entries × 1,000 chars, capped at both ends; body ~5 MB, image 4 MB, `meta` 64 KB. *(reasoning)*

**Resolution — one binding constant set** (goes into `packages/contracts` as schema-level constants in Phase 1; client clamps are UX only, server caps are the control):

| Constant | Binding value | Source of the number |
|---|---|---|
| Console entries | **100, drop-oldest**, `droppedCount` surfaced ("N earlier messages dropped") | ARCHITECTURE's count; FEATURES' 50 is the conservative floor, PITFALLS' 200 unreachable under the byte cap below |
| Console per-message / per-arg | **2,048 / 1,024 chars**, serialization depth 3, cycle-safe, **eager serialization at capture time** (drop references) | PITFALLS (supersedes ARCHITECTURE's 1,000) |
| Console `stack` field | **8,192 chars** per entry (separate field) | FEATURES' market value — stacks are legitimately long |
| Console total serialized buffer | **48 KB**, drop-oldest | **Adjusted from PITFALLS' 64 KB** — see reasoning |
| `meta` JSON part | **64 KB** serialized | ARCHITECTURE ≈ PITFALLS (agree) |
| Text field caps | title **200**, description/note **5,000**, `user.name` **120**, `user.email` **254**, `user.id` **64**, URL path **2,048**, `Enricher` values **512** | PITFALLS (description supersedes ARCHITECTURE's 2,000) |
| Total request body | **5 MB** (`bodyLimit` → 413); reject on `Content-Length` before read **plus** a streaming byte counter | PITFALLS/ARCHITECTURE (agree) |
| Multipart limits | `files: 1`, file part **≤ 4 MB**, `fields: 8`, `fieldSize` 4 KB, `headerPairs` 1 KB | PITFALLS |
| Encoded image | target **≤ 800 KB**, hard cap **2 MB** (re-encode q 0.6 → 0.5 → downscale 0.75×) | PITFALLS |
| Decoded-image bomb guard | from headers **before decode**: `w,h ≤ 8192`, `w×h ≤ 25 MP`; SVG rejected unconditionally; `image/webp`/`image/png` only, magic-byte verified | PITFALLS |
| Rate limits | **10 req/min per `project_key` + 30 req/min per IP + 2,000 reports/day per project** (custom `@fastify/rate-limit` store incrementing both counters; `trustProxy` set explicitly; 429 + `Retry-After`; NAT caveat documented, env-tunable) | PITFALLS (supersedes FEATURES' single-dimension 20/min per IP and ARCHITECTURE's "10/min burst 5") |
| Retry / dedup | 3 attempts, backoff 1 s / 4 s / 10 s ±25 % jitter, 15 s per-attempt timeout; idempotency key = client report UUID, reused across retries; `UNIQUE (project_id, idempotency_key)` with response replay | ARCHITECTURE ≈ PITFALLS (agree) |
| Transport lanes | Lane 1: plain `fetch` (above). Lane 2: IndexedDB queue (meta + Blob) on failure/`pagehide`, flushed on `pageshow` with the same key, entries destroyed after success, bounded count/bytes, **never `localStorage`**. Lane 3 (optional): **≤ 60 KB metadata-only flush** / ≤ 1 KB receipts via `keepalive`/`sendBeacon` — never image-bearing | H-9 correction + PITFALLS |

**Reasoning.** PITFALLS' set is threat-driven and must win over market averages where they conflict, but FEATURES' numbers are the sanity band. Two deliberate adjustments make the set internally non-contradictory: (1) the console byte cap drops 64 KB → **48 KB**, because PITFALLS justified 64 KB as "a metadata-only flush always fits" — yet 64 KB of console *alone* already busts the ≤60 KB flush lane (which itself sits under the 64 KiB spec cap). 48 KB console + envelope < 60 KB makes that invariant actually true. (2) FEATURES' **100 KB total payload** is rejected outright: our own WebP screenshots are 60–150 KB typical / up to 800 KB — a 100 KB payload cap would reject normal reports. Likewise FEATURES' **10 MB image** cap is replaced by 4 MB part / 2 MB encoded: it contradicts the 5 MB body cap and invites exactly the storage/decode bombs H-7 documents. Entry count settles at 100 (ARCHITECTURE) because 200 entries cannot exist under a 48 KB cap.

### Conflict 2 — capture adapter: single default vs fallback chain (and chain order)

- **FEATURES/STACK position:** default `DisplayMediaCapture` with `preferCurrentTab`, **plus a mandatory graceful fallback** — but the second link is the DOM-serialization adapter (D-08 retained) or "report without screenshot". *MEDIUM/LOW mix.*
- **ARCHITECTURE position:** the chain is display-media → **DOM-serialize → manual upload** (three `CaptureSource` adapters, `id` union already models all three). *(reasoning)*
- **PITFALLS (H-4/H-5) position:** `getDisplayMedia` + `preferCurrentTab` where available and **file-attach as the shipped pair**; DOM serialization is the **optional third** adapter under D-08 constraints. *MEDIUM.*

**Resolution — the chain is settled (this is the Q-06 correction), and PITFALLS' ordering wins:** `display-media` (default) → **manual file upload** (shipped, mandatory fallback) → `DOM-serialize` (optional lazy third adapter, loaded only when the chain reaches it, with blank-detection and a canvas-taint probe). UI copy on any fallback: "screenshot unavailable — send anyway?" — never a silently blank image.

**Reasoning.** The chain beats a single adapter unanimously (iOS has no `getDisplayMedia`; cross-origin iframes need `allow="display-capture"`; enterprise policy can disable it) — that part is not in dispute. The ordering is: DOM-serialization carries D-08's **silent-failure class** (cross-origin images, video, WebGL, fonts, closed shadow roots) plus M-5's canvas tainting (`getImageData` throws at send time) and costs 8–14 KB. Putting it second means iOS users — the very population the fallback exists for — pay bytes for an adapter most likely to fail silently on their device. Manual upload is deterministic, ~1–2 KB, works everywhere, and has no failure class beyond "user picked a non-image" (handled by the same magic-byte allowlist). DOM-serialize stays in the build only as a lazy optional adapter, and its byte cost is the core of the budget-surprise risk below.

### Conflict 3 (surfaced during synthesis) — durability mechanism at unload

- **ARCHITECTURE / H-9 correction position:** IndexedDB pending queue flushed on next `pageshow`, keyed by idempotency key. *(reasoning + established RUM practice)*
- **PITFALLS position (constants table):** **no persisted pending reports** (persistence re-opens a C-5/privacy surface) — keep the tab open with a visible "retrying" state instead. *MEDIUM.*

**Resolution — IndexedDB queue (the mandated correction), with queue hygiene.** Entries hold only what the report itself holds *after* C-5 scrubbing and R-08 stripping (the privacy surface is identical to the send path, not wider); entries are destroyed on successful flush or after a bounded TTL; the queue is capped (count and bytes); `localStorage`/`sessionStorage` remain forbidden (grep-gated). A visible "retrying" state is kept *in addition* — PITFALLS' UX instinct is right, its storage prohibition is what gets overruled.

**Reasoning.** FEATURES rates "the report arrives even if the user closes the tab immediately" as **table stakes**, and H-9 proves `keepalive`/`sendBeacon` cannot carry a screenshot. Stay-open-only means every mobile/user-navigation report is a coin flip (unload delivery is unreliable generally). The privacy objection is real but is a hygiene question, not an architecture objection — and PITFALLS' own C-5 controls (closed schema, scrubber) apply to queued bytes by construction.

*Minor, folded into Conflict 1: description/note cap 2,000 (ARCHITECTURE) vs 5,000 (PITFALLS) → 5,000 (both are schema constants; the larger still bounds the XSS/DoS surface).*

## Hard Constraints for Roadmap

*Binding on every phase. The corrected masking primitive and transport constraint are called out explicitly — they supersede the earlier wording wherever it appears.*

1. **Corrected masking primitive (supersedes R-13 wording).** Automatic SEC-01 masks (`input[type=password]`, `[data-watchbug-sensitive]`, credential/token/card patterns) = **flat opaque fill only** (α=255). User pixelation is opt-in: block ≥ `max(8 px, 2× cap-height)` device px, region snapped outward to the block grid, α=255, fresh **lossy** re-encode after destruction. Blur, `ctx.filter`, CSS overlays, semi-transparent fills and blocks < 8 px are prohibited. Ordering **T1 (auto, before display) → T2 (mask baked at stroke end) → T3 (flatten ink, re-bake masks LAST, fresh `toBlob`)** is an invariant; masks are not undoable; exactly **one** flattened working bitmap and **one** `toBlob` sink in the SDK. The CA-02 e2e decodes the outgoing image and asserts the masked region's original pixels are absent **including at region boundaries**.
2. **Transport constraint (supersedes R-02's `Transport` note).** No image-bearing report may depend on `keepalive`/`sendBeacon` (64 KiB spec cap). Plain `fetch` + idempotency-keyed bounded retry + IndexedDB durability queue flushed on `pageshow`; server dedupes on `(project_id, idempotency_key)`. The navigate-away e2e ("submit, immediately `page.goto`, assert stored or visibly retrying — never a silent drop") is part of the one Playwright suite.
3. **Size budget (R-01/CA-03):** 45 KB core / 25 KB per lazy chunk / 80 KB total runtime, gzipped, enforced by `check:size` **on every PR with a printed per-entrypoint delta**. SDK has **zero runtime dependencies**; contracts enter the SDK as `import type` only. Any PR growing `watchbug.js` states its gz delta.
4. **Isolation (INV-01/INV-02/R-14/CA-04):** closed Shadow DOM in production + `SHADOW_MODE` build flag with a root registry for e2e; one global (`window.Watchbug`) or ESM export; no prototype patching; no stylesheets/classes in host `head`/`body`; no `rem`, no `part=`, `--wb-` prefixed variables only. Host-element defence = inline `!important`, `documentElement` last child, `all: initial` + explicit re-declaration.
5. **Privacy/telemetry (SEC-01…SEC-03, R-08, R-09):** masking destructive on `ImageData` before encode; URL = scheme+origin+path only; `user` rides only when host-supplied and `privacy.userIdentity !== false`; **no host cookies/storage/auth headers read or sent — and no secrets in the payload** (closed schema, CI grep gate in `packages/sdk`, secret scrubber, no `document.referrer`). Only the write-only `project_key` leaves the browser, and it travels via init/data-attr, **never a URL query string**.
6. **Retention (R-10 as corrected):** identity TTL **and artifact TTLs** (image + `consoleLogs`), env-configurable, evidenced in `purge_runs`; erasure deletes blobs; integration docs carry an Art. 13 snippet + Art. 28 DPA template.
7. **API hardening (SEC-05, C-3, C-4, H-7):** the reconciled constant set (Conflicts #1) is binding at the schema level; rate limit per IP **and** per project key; sanitize-on-ingest **and** escape-on-render (React text nodes, zero `dangerouslySetInnerHTML`); image allowlist webp/png magic-byte verified, SVG rejected unconditionally, re-encode on ingest where feasible; blobs served only via the authenticated API with nosniff + CSP + `attachment` + allowlisted content-type; volume mounted **only** in `api` (CI compose assertion).
8. **Auth (SEC-06, R-05, M-4):** single admin from `.env`; Argon2id (`@node-rs/argon2`); JWT TTL ≤ 8 h in `__Host-` / `HttpOnly` / `Secure` / `SameSite=Lax` cookie; **all mutations are POST/PATCH/DELETE** (no state-changing GET); `Origin` verification on cookie-auth'd mutations; documented TLS story (or a loudly-warned dev flag).
9. **Deployment (INV-03 + correction):** one `docker-compose.yml`, exactly three services (`api`, static `panel`, `db`), provider-agnostic; **nginx reverse-proxies `/api` → `api` for same-origin cookie auth**; attachments on a filesystem volume.
10. **Verification (R-12):** e2e + property assertions only — **one** Playwright suite ≈20 assertions mapping 1:1 to CA-01…CA-05, plus `check:size`. **No unit-test suites, no coverage thresholds** — and none may be proposed.
11. **Scope (mission-brief §2 / R-17):** no third-party integrations (Jira/GitHub/Slack/Trello…), no session replay or video recording, no AI error analysis, no gamification or auto-fix suggestions, no managed multi-tenant SaaS/payments, no third-party OAuth2/SSO, no multi-user panel accounts, no unit-test suites. R-02's reserved ports remain **seams only**. Scope is cut by coherence, never by calendar.
12. **License (R-07):** Apache-2.0 with `NOTICE`; repository stays private until Q-05 (institution IP policy) is confirmed. All runtime dependencies must be permissive (this is why `dompurify`'s dual license was rejected).

**Likelietest budget surprise:** the dual-format / lazy-chunk build interplay. esbuild accepts one format per build call and code-splits ESM only, so IIFE + ESM × core + annotator = **four emitted artifacts** with the annotator loaded by `import()` (ESM) and script-tag injection (IIFE). Worst-case arithmetic is already over budget on paper: 45 + 25 + 14 (DOM-serialize fallback) = **84 KB > 80 KB**. Resolution options, to be settled against real `check:size` numbers in Phase 7: count optional-adapter bytes only in the fallback scenario where the editor chunk is already resident (the chain-fallback and editor-open states rarely coexist), or cap the editor at 21 KB.

## Phase Goal

**As an** end user on any host page, **I want to** open the Watchbug widget and file a screenshot-backed bug report with one gesture, **so that** the developer gets a report they can reproduce — with everything sensitive already destroyed in the pixels — and neither the report nor its screenshot ever leaves the developer's own infrastructure.

<assumption_delta_decision>
- Detector signals (vocabulary false positives on re-read of the phase scope): `fallback` fired on "the silent WebP→PNG fallback" (a codec fallback, not a second source of truth) and `custom` fired on "`--wb-` custom properties" (CSS custom properties, not a derived→chosen modelling transition). - **Noun now primary:** the module's named export `init` (the `packages/sdk/src/index.ts` public surface).
- **Decision: `promote`.** The module export is the primary identity; `window.Watchbug` is the IIFE build-format *projection* of that same module namespace (`globalName: 'Watchbug'`), not a parallel API. One code path serves both loaders, so the global and the import cannot drift. INV-02's "exactly one global" continues to hold for the script-tag lane; the ESM lane creates no global at all.
- Rationale: adding a second, separately-maintained global-shaped API alongside the module would be `add-alongside` debt — a later variant could never be confirmed as the default. No accepted debt.
- Suggested invariant (optional companion, already in the WDG-04 e2e row in 02-01 and the INT-05 row in this plan): *every supported consumption mode boots the same widget and files the same report payload; the IIFE lane adds exactly one window property and the ESM lane adds none.*

## Phase Goal

**As an** end user on any host page, **I want to** open the Watchbug widget and file a screenshot-backed bug report with one gesture, **so that** the developer gets a report they can reproduce — with everything sensitive already destroyed in the pixels — and neither the report nor its screenshot ever leaves the developer's own infrastructure.

**This plan's slice:** the privacy core proven at the artifact level — the complete P2-D-07 auto-redaction catalog (password fields, credential/token patterns with Luhn-validated cards, `data-watchbug-sensitive`) destructively flat-filled on `ImageData` before any encode, with the decoded outgoing bytes asserted to contain none of the matched pixels (the CA-02-style proof), and the H-1 bitmap-space geometry proven across DPR and zoom.

<objective>
Close PRV-01/PRV-02/PRV-03 where they must be closed — in the bytes that actually left the browser. Complete the P2-D-07 catalog in `redact/patterns.ts` (JWT shape, bearer-token shape, `key=/token=/secret=/password=` assignments, Luhn-validated card sequences — hand-rolled, no dependency per PRF-04), keep the whole-element / whole-text-node granularity with outward-rounded bitmap rects (P2-D-08, H-1), enforce the fail-closed behavior on redaction errors, and prove each family with e2e rows that intercept the outgoing request, decode the attached image, and assert the original pixel values are absent from the masked region including its boundary.

Purpose: T1 redaction ordering is the product's core privacy promise ("nothing sensitive ever leaves the browser"); a regex miss or a misregistered mask is a leak, and only artifact-level assertions can prove otherwise. These rows are the CA-02-class evidence Phase 3's user-masking work extends.

Output: complete `redact/{patterns,redactor,geometry}.ts`, the Pitfall-1 gate strategy resolved in `scripts/gate.mjs`, and green PRV-01/02/03 + HiDPI geometry rows in `e2e/sdk.spec.ts`.
</objective>

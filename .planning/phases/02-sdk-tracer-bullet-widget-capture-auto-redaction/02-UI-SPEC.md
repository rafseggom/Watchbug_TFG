# Phase 2 — UI Design Contract

> Visual and interaction contract for the SDK widget surfaces (floating launcher + status panel).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope of this Contract

This phase has exactly **two UI surfaces**, both rendered inside the widget's closed Shadow DOM
(only surface: `packages/sdk`):

1. **Floating launcher button** (WDG-01) — the sole end-user affordance; one click captures AND
   submits (P2-D-01).
2. **Floating status panel** (P2-D-02) — progress + result feedback, and the "dialog content"
   CA-04 asserts under hostile host CSS.

**Not covered here (locked out of Phase 2):** report composer / form (Phase 3, CAP-02/03/PRV-07),
annotation editor (Phase 3), i18n switcher (Phase 3, WDG-06), any new panel screen — `apps/panel`
already renders the landed report and receives **no new UI code** this phase.

**Governing hard constraints (non-negotiable):** INV-01 (closed Shadow DOM, zero host leakage),
INV-02 (one global `window.Watchbug`), RNF-01/PRF-01/PRF-04 (≤ 45 KB gz core, **zero runtime npm
dependencies**), RNF-02 (host CSS cannot break the widget), R-13/A-01 (flat opaque α=255 fill is
the only masking primitive), R-03/P2-D-04 (single ID→English `strings.ts` map, no i18n yet),
px-only units (H-2/H-3 — zero `rem`/`em`).

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — forbidden by PRF-04 (zero runtime deps) and RNF-01 (45 KB gz budget) |
| Icon library | none — hand-rolled inline SVG (≤ 2 glyphs), no icon package |
| Font | `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` (P1-D-06 `--font-sans` value; no webfont bytes, no external requests from the widget) |

**Why `Tool: none` is correct here, not a gap:** the widget is vanilla TypeScript rendered through
`WidgetHost` into a closed shadow root. shadcn/Radix are React packages and would consume the
entire 45 KB gz budget and violate PRF-04 outright. `apps/panel` (React + Vite) is likewise
hand-rolled on `apps/panel/src/tokens.css` (locked decision P1-D-06) with no `components.json`
anywhere in the repo (verified by recursive search, 2026-10-17). All widget CSS is hand-written
inside the shadow root.

**shadcn gate:** not applicable — no React surface is in scope and no `components.json` exists.
**Registry vetting gate:** not applicable — no registries are consumed.

## Typography

Exactly 3 sizes, exactly 2 weights. All sizes in px; declared explicitly on the shadow wrapper
(the `all: initial` reset strips inherited font — every used property must be re-declared).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (in-flight status text) | 15px | 600 | 1.5 |
| Label (hints, buttons, retry counter) | 13px | 400 (600 on buttons) | 1.4 |
| Heading (terminal status message: "Report sent ✓" / failure headline) | 19px | 600 | 1.2 |

- Font family: `system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif` (re-declared on the
  wrapper; host `font`, `color`, `letter-spacing`, `text-align`, `direction: ltr` are reset).
- No webfonts, no `@font-face`, no external font requests (size budget + H-8 neutrality).
- Text color inherits from the wrapper (`#1b1f26`); never `currentColor` from the host.

## Color

Palette values mirror the locked Phase 1 token set (`apps/panel/src/tokens.css`, P1-D-06, light
values) for brand coherence, re-declared locally as `--wb-*` custom properties inside the shadow
root. The widget uses a **single fixed light palette** (see Assumption A-3).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Status panel surface |
| Secondary (30%) | `#eef0f4` (surface-alt) + `#d6dae1` (border) | Button rest backgrounds, panel 1 px border, spinner track |
| Accent (10%) | `#2f6feb` | Launcher fill, "Try again" button fill, focus ring, spinner arc |
| Destructive | `#b3261e` | Failure `✕` glyph and failure headline only |

Supporting inks (text only, not part of the 60/30/10 split):
- Body ink `#1b1f26` (on `#ffffff`: ≥ 12:1), muted ink `#5b6472` for hints (≥ 4.5:1 — AA).
- Success glyph `#1e7a46` (P1-D-06 `--color-status-resolved`).
- Launcher glyph `#ffffff` on `#2f6feb` (4.57:1 measured — AA for the button label case).
- Hover: `#2962cf`, active/pressed: `#2456b8` (precomputed darker accent; no `filter`).

**Accent reserved for:** the launcher button fill, the "Try again" action fill, the focus ring,
and the in-flight spinner arc. **Nothing else** — no accent text, no accent borders, no accent
backgrounds.

**Destructive reserved for:** the terminal failure state's `✕` glyph and its headline. There are
no destructive *actions* in this phase.

Every color is declared as a `--wb-*` property on the shadow wrapper — zero hardcoded colors in
component code (P1-D-06 discipline), zero host-inherited color.

## Widget Geometry & Isolation Contract (H-2/H-3 — architecture-loaded)

**Host element** (custom element appended as the **last child of `document.documentElement`**,
re-appended by a light `MutationObserver` if `documentElement` is replaced), styled with inline
`!important` (inline `!important` outranks author `!important` — this is what defeats hostile
`* { display: none !important }`):

```
position: fixed !important; z-index: 2147483647 !important;
right: 24px !important; bottom: 24px !important;
margin: 0 !important; padding: 0 !important; border: 0 !important;
background: transparent !important; width: auto !important; height: auto !important;
pointer-events: none !important;
```

Interactive descendants set `pointer-events: auto` so the host box never swallows host-page clicks.

**Shadow root:** closed (`mode: 'closed'`) in production; `SHADOW_MODE=open` e2e build exposes
roots via a module-scoped registry for Playwright (R-14). The shadow `<style>` element lives
**inside** the shadow root (not `adoptedStyleSheets`), begins with `all: initial` (on `:host`
and the inner wrapper), then **explicitly re-declares every used property**: `box-sizing`,
`font-family`, `font-size`, `line-height`, `color`, `direction`, `cursor`, `text-align`.
`--wb-*` custom properties are declared on the inner wrapper only. **No `part`, no `::theme`,
zero `rem`/`em`, zero stylesheets or classes in host `head`/`body`, zero external requests.**

**Layout (all fixed, px-only):**
- Launcher: 48×48 px, radius 24 px (circular), accent fill, 24×24 white bug glyph centered.
- Status panel: `position: fixed; right: 24px; bottom: 88px` (24 inset + 48 launcher + 16 gap);
  `width: min(320px, calc(100vw - 48px))`; padding 16 px; radius 8 px; `#ffffff` on
  `1px solid #d6dae1`; elevation `0 8px 24px rgba(27,31,38,0.18)`.
- Spinner 12×12 px, 4 px gap to status text. Hint text 13 px `#5b6472`, 8 px above the action row.
- Action row: buttons 36 px tall, 8 px gap, right-aligned.

**Hide/restore for capture (P2-D-05, locked):** synchronously inside the launcher's gesture
handler, **before** `getDisplayMedia`, the host gets inline `display: none !important`; the
property is removed after raw `ImageData` is obtained. The capture pipeline asserts the host is
hidden immediately before `drawImage`/`getImageData` and fails **loudly** (visible error state,
M-6) otherwise (P2-D-06) — the guarantee lives in code, not call ordering.

## Interaction & State Contract

### State machine (status panel)

| State | Trigger | Visible UI | Copy key | Exits |
|-------|---------|------------|----------|-------|
| `idle` | init, or after terminal-state dismissal | launcher only | `launcher.label` (aria-label) | launcher click → `capturing` |
| `capturing` | launcher click (host hidden during prompt + frame grab) | status panel (visible from host restore onward) + spinner | `status.capturing` | ImageData OK → `sending`; capture error → `failedCapture`; blank probe → `failedBlank` |
| `sending` | POST in flight | status panel + spinner | `status.sending` | 2xx → `sent`; transient failure → `retrying`; 4xx → `failedRejected` |
| `retrying` | transient failure, attempts remaining | status panel + spinner | `status.retrying` (`{n}`/`{max}`, max=3) | success → `sent`; next transient → `retrying`; exhausted → `failedNetwork` |
| `sent` | 2xx response | terminal panel, success glyph | `status.sent` | auto-dismiss after **5 s** → `idle`; `Dismiss` → `idle` |
| `failed*` | terminal failure | terminal panel, error glyph + hint + buttons | `status.captureFailed` / `status.blankCapture` / `status.sendFailed` / `status.rejected` | `Try again` → `capturing` or `sending` (see retry semantics); `Dismiss` → `idle` |

**Re-entrancy:** launcher clicks are ignored unless state is `idle` (one report per gesture; the
launcher renders disabled/dimmed while a panel is open).

**Auto-retry (P2-D-03, locked):** transient failures only (network error, 15 s timeout, 5xx, 429)
— 3 attempts, backoff 1 s / 4 s / 10 s ±25 %, **same `Idempotency-Key` on every attempt**.
Contract 4xx (400/401/403/413) fail **immediately**, no auto-retry, showing the server reason.

**Manual "Try again" semantics (Assumption A-2):** when a valid encoded report exists (send-side
failure: network / timeout / 5xx exhausted / 429) → re-POST the same bytes with the **same**
`Idempotency-Key` (server dedupe = exactly-once). When no valid report exists (capture failure,
blank probe) or the failure is a contract 4xx → restart the full gesture with a fresh key
(a new `getDisplayMedia` needs a fresh user gesture anyway — the click supplies it).

**Never silent (M-6 / P2-D-12):** a blank capture, a failed capture and a failed send are always
loud terminal states with copy + an action. A silently blank image is never sent.

### Motion

- Panel entrance: `opacity 0→1` + `translateY(4px→0)`, 120 ms ease-out.
- Spinner: 700 ms linear rotation.
- `@media (prefers-reduced-motion: reduce)`: entrance transition removed (instant), spinner static.
- CSS-only, inside the shadow root. No animation library, no JS timers for animation.

### Accessibility

- Launcher is a real `<button>` with `aria-label` from `launcher.label`; keyboard reachable in
  document tab order; `:focus-visible` ring 2 px `#2f6feb`, 2 px offset.
- Status panel text container: `role="status" aria-live="polite"` (in-flight transitions
  announced without stealing focus). The terminal **failure** state additionally renders its
  headline in `role="alert"` (assertive).
- No focus stealing on open; focus only moves naturally (Tab) to `Try again` / `Dismiss`.
- `Escape` dismisses an open terminal panel (one document-level `keydown` listener, removed on
  widget teardown — see Assumption A-7).
- All actionable hit targets ≥ 24×24 px (WCAG 2.2 AA); launcher 48×48.

## Copywriting Contract

All visible copy lives in **one `strings.ts` map (P2-D-04, locked)**: ID keys → English values,
no locale detection, no switcher. The shape below is the Phase 3 pluggability contract — adding
`es` must be additive and local to the strings layer.

```ts
// packages/sdk/src/strings.ts
export const strings = {
  'launcher.label': 'Report a bug',
  'status.capturing': 'Capturing…',
  'status.sending': 'Sending…',
  'status.retrying': 'Retrying ({n} of {max})…',
  'status.sent': 'Report sent ✓',
  'status.captureFailed': "Couldn't capture the screen.",
  'status.captureFailed.hint': 'Nothing was sent. Allow screen sharing, then try again.',
  'status.blankCapture': 'The capture came back blank.',
  'status.blankCapture.hint': 'Nothing was sent. Try again — if it keeps failing, the page may be too large to capture.',
  'status.sendFailed': "Couldn't send the report.",
  'status.sendFailed.hint': 'Nothing was sent. Check your connection, then try again.',
  'status.rejected': 'The server rejected the report.',
  'action.retry': 'Try again',
  'action.dismiss': 'Dismiss',
} as const;
export type StringId = keyof typeof strings;
export function t(id: StringId, vars?: Record<string, string | number>): string;
```

`t()` performs `{placeholder}` replacement only (a few bytes); Phase 3 adds
`stringsEs: Record<StringId, string>` plus a locale resolver without touching core.

| Element | Copy |
|---------|------|
| Primary CTA | Launcher button (the only CTA): **"Report a bug"** — one click captures and submits (P2-D-01) |
| Empty state heading | Not applicable — Phase 2 has no data-collection surface (composer arrives Phase 3); `idle` shows the launcher only |
| Empty state body | Not applicable (same reason) |
| Error state | `status.*Failed` headline + `*.hint` ("Nothing was sent." + what to do next), plus server reason for 4xx (`status.rejected` + reason, truncated to 240 chars) and buttons **"Try again"** / **"Dismiss"** |
| Destructive confirmation | None — this phase has no destructive UI action |

State transitions in the locked flow (English): `Capturing…` → `Sending…` → `Retrying (n of 3)…`
→ `Report sent ✓`.

## Open Questions & Assumptions (for the planner)

> Derived defaults where locked artifacts left a gap. None contradict a locked decision.

| # | Question | Default (this contract) | Why / what could change it |
|---|----------|--------------------------|----------------------------|
| A-1 | "Capturing…" visibility window vs locked hide-order (P2-D-05 hides the host *before* `getDisplayMedia`) | Honor the lock: the host is invisible during the picker + frame grab; `status.capturing` is visibly rendered during the processing tail (blank probe → redact → downscale → encode) before `Sending…` | Making "Capturing…" visible *during* the picker would require delaying the hide until just before `drawImage`, contradicting P2-D-05's "synchronously in the gesture handler, before `getDisplayMedia`". Treat as locked; revisit only via the owner |
| A-2 | What "Try again" does after each failure class | Send-side failure with valid bytes → same-bytes / same-key re-POST; capture-side failure or contract 4xx → restart full gesture with fresh key | P2-D-03 governs only *automatic* retries; this extends its intent to the manual button |
| A-3 | Widget theme on dark host pages | Single fixed light palette (matches P1-D-06 light values); no `prefers-color-scheme` in Phase 2 | No requirement demands theming; a dark variant is additive alongside Phase 3's i18n (both plug into the shadow-local layer) |
| A-4 | Launcher placement configurability | Fixed `right: 24px; bottom: 24px`; **no** init option in Phase 2 | `window.Watchbug.init` is a public interface — adding options later is additive but is a consultation trigger (AGENTS.md) |
| A-5 | Success-state lifetime | Auto-dismiss 5 s, manual `Dismiss` earlier | Keeps the widget from lingering over the host app |
| A-6 | Server-reason rendering | Show reason code + text, truncated to 240 chars with ellipsis | Phase 1 responses are structured (`401/413/429/400` + reason); cap bounds the panel |
| A-7 | `Escape`-to-dismiss mechanism | One document-level `keydown` listener (Escape only), registered by the host module and removed on teardown | INV-01 forbids *leaking* globals/styles; a removable listener is not a leak, but the isolation verifier (CA-04 e2e) should assert no residual globals/prototypes |
| A-8 | 12 px intermediate spacing (P1-D-06 has `--space-3: 12px`) | Dropped — the widget uses only 4/8/16/24/32 px | Keeps the declared scale minimal; no visual difference at this surface size |

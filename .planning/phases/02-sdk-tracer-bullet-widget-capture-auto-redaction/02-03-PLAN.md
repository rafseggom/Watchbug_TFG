## Phase Goal

**As an** end user on any host page, **I want to** open the Watchbug widget and file a screenshot-backed bug report with one gesture, **so that** the developer gets a report they can reproduce — with everything sensitive already destroyed in the pixels — and neither the report nor its screenshot ever leaves the developer's own infrastructure.

**This plan's slice:** capture fidelity and honest failure — the capture seam proven per engine (CAP-01), the widget provably absent from capture bytes (CAP-04), the deterministic downscale/encode ladder meeting the size contract without blanking on HiDPI (CAP-05), the 9-pixel blank probe, the non-tab-surface refusal, and the M-3 fallback sniff.

<objective>
Close CAP-01/CAP-04/CAP-05 at the artifact level: the two-tier capture stub seam runs the real probe → redact → encode → transport pipeline on all three Playwright engines, the widget's own pixels are provably absent from the decoded outgoing image, the P2-D-10/11 ladder clamps DPR to 2 and downscales to ≤ 16 MP / ≤ 800 KB target / 2 MB hard without going blank at `deviceScaleFactor: 2`, and every capture failure (blank frame, non-tab surface, prompt rejection) is a loud visible state per M-6/P2-D-12.

Purpose: capture is where the phase's two privacy promises meet reality — the widget must not appear in its own screenshot (CAP-04/P2-D-05/06) and no blank or unverifiable frame may ever be sent silently (M-6, Pitfall 7). These rows are the CA-01/CA-04 evidence the release gate re-runs in Phase 7.

Output: hardened `capture-source.ts`/`pipeline.ts`/`encode.ts`, the complete `e2e/helpers/capture-stubs.ts` two-tier stub with the forced-PNG encode stub, and green capture rows across chromium + firefox + webkit in `e2e/sdk.spec.ts`.
</objective>

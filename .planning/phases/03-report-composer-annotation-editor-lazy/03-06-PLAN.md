## Phase Goal

**As an** end user of a web app, **I want to** compose a complete bug report or plain feedback -- capture or attach an image, annotate it, destructively mask anything sensitive, review it, and file it -- with the editor fetched on gesture and the whole widget UI in English or Spanish, **so that** the developer receives a report they can reproduce and neither the report nor its screenshot ever leaves the developer's own infrastructure.

**This plan's slice:** the irreversible mask -- the user's own redaction -- plus the CA-02 proof that a masked region is gone from the encoded bytes, including its boundary, including after later ink is drawn over it.

<objective>
Implement user masking as destructively baked post-mask patches and prove the destruction at the artifact level with the suite's existing pixel-analysis machinery.

C-2/A-04 forbid a pre-mask copy anywhere in the editor's data model -- and C-2 also forbids an offscreen base layer, so the editor holds exactly one bitmap -- T2 requires the bake at stroke completion, and T3 requires masks to be the last masking operation before the encode and a T1 re-run after them. The shape that satisfies all four at once is a post-mask patch plus a single shared buffer: read only the dragged rect, destroy it in the canvas, write the destroyed bytes back into the draft's own buffer, and store the destroyed pixels as the patch. Export replays the patches, then re-runs T1, so annotation ink physically cannot sit on top of a mask -- in the preview or in the bytes.

R-13/A-01 also constrain the primitives: flat opaque fill (alpha 255) is the only automatic one, pixelation is opt-in at a block of at least `max(8 px, 2x cap-height)` snapped outward, and gaussian blur is prohibited as partially invertible. P3-D-09 relaxes the per-mask confirm to once per session, which is a UX decision, not a weakening of irreversibility.

Purpose: PRV-04 is the phase's privacy core. CA-02's assertion machinery already exists in the suite (`analyzeRedaction` + `expectMaskedAndTargeted`, plus the magenta marker painted by `PAINT_FRAME` with the redactor's own outward rounding), so this plan adds only the drag, the pixelate/confirm behaviour and the DPR matrix -- no new pixel analysis, and no second geometry implementation.

Output: `annotator/masks.ts`, the shared fill/pixelate primitives in `redact/masks.ts`, the mask drag and confirm dialog, `encodeFinal`'s mask replay completed, and the `ANN-05`/`PRV-04` rows including the cross-stroke and DPR proofs.
</objective>

## Flagged assumptions & planner decisions (surfaced, not silent)

- **The bake writes into the same buffer the editor redraws from** (C-2/A-04, research F5 read as a prohibition on *pre-mask* state). 03-05's `open()` receives the draft's own `ImageData` and returns that same instance, so a single buffer is the working bitmap, the redraw source and `draft.image`. `bakeMask` destroys the rect in the canvas and writes the identical destroyed pixels into `base`, which is why no pre-mask copy exists anywhere: undo is a redraw from a buffer that already holds flat fill (or block means) in every masked rect, and the patch replay is idempotent rather than the only thing keeping the mask alive. The alternative -- an immutable base plus a patch replay -- silently retains the original pixels of every masked region for the whole session, and the encoded output would still look correct, so only the data-model assertion catches it.
- **Mask pixelation proof form (deviation from the phrase used in 03-VALIDATION.md).** "No original marker colour survives" cannot hold for pixelation when the source region is uniform: a block made entirely of the marker colour averages to that colour. The assertion is therefore mechanical -- grid-snapped region, every block uniform, alpha 255, distinct colours <= block count -- which is what actually proves block averaging happened. The fill mode keeps the strict "zero original pixels" form (CA-02).
- **`capHeightPx` is measured, not assumed.** A hard-coded cap height would be an unverified claim about the platform font; `actualBoundingBoxAscent` on `'H'` at the label size is a few lines and is checked against the block-size floor of 8 px.
- **Masks persist across a Review -> Edit round trip** by seeding `open()` from `draft.masks`; the editor never re-derives a mask from pixels it no longer has.
- **The mask tool button existed in 03-05 but was inert**; this plan is where it becomes functional and where its recovery rows live.

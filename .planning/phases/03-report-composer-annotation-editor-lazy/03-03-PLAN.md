## Phase Goal

**As an** end user of a web app, **I want to** compose a complete bug report or plain feedback -- capture or attach an image, annotate it, destructively mask anything sensitive, review it, and file it -- with the editor fetched on gesture and the whole widget UI in English or Spanish, **so that** the developer receives a report they can reproduce and neither the report nor its screenshot ever leaves the developer's own infrastructure.

**This plan's slice:** the composition surface itself -- capture lands in a real form (title, type, note, image), the user reviews the exact artifact before sending, and every core surface speaks English or Spanish. The annotation editor, the mask tool and image attachment are later plans; this one ships the frame they mount into.

<objective>
Replace the Phase 2 one-shot shortcut with the composer + review screen inside the closed shadow root, wire the pipeline split that puts a human between capture and encode, and put the core copy in both locales.

Phase 2's flow is `gesture -> capture -> redact -> encode -> send` in one function with a fixed `type: 'bug'` title and no form; P2-D-01's auto-title is the placeholder P3-D-02 replaces, and the 320 px status panel is the only view the renderer has. This plan splits the pipeline at the pixel boundary (`runCaptureStage` returns an already-T1-redacted `ImageData` plus bitmap-space mask rects; `encodeFinal` is the only encode path), adds a screen router (`idle | status | composer | editor | review`), and builds the composer/review views on the `status-panel.ts` skeleton.

Purpose: PRV-07 ("an end user can review and edit the capture before it is sent") is only meaningful if the review shows the bytes that will leave the browser -- so encoding happens once at Review entry and the review canvas renders that blob decoded back. WDG-06 is implemented here for the core surfaces because A-2 loads the editor chunk only at `Annotate image`: the form's Spanish copy must exist before, and independently of, that download.

Output: `capture/pipeline.ts` split with a `Draft` type, `encodeFinal()` in the single-sink module, `widget/composer.ts` + `widget/review.ts` with token-only CSS and no HTML sink, `strings.ts` carrying `stringsEs` plus the locale resolver, the router in `index.ts`, the Wave 0 `e2e/helpers/composer.ts`, and `PRV-07`/`WDG-06`/form rows in the one suite.
</objective>

## Flagged assumptions & planner decisions (surfaced, not silent)

- **i18n placement (discretion, decided here).** ROADMAP says "i18n dictionaries live in the lazy chunk, never in core". Read literally that makes the *composer's* Spanish copy conditional on a download that A-2 says may never happen (and never happens at all in the text-only path). The plan implements the split: core carries launcher/status/action/composer/review/mask-confirm/i18n strings in both locales; the lazy chunk carries `editor.*` only (03-05). `editor.loading`/`editor.load.error*` stay in core because the `Annotate image` button renders them before any chunk exists. Cost measured against 35.7 KB core headroom: ~1.5-2 KB gz.
- **Encoding happens at Review entry, not at Send** (research A8). It makes the review literally the artifact and keeps `Send report` network-only.
- **`Draft.t1` is bitmap-space** and measured at the read instant (WR-01/H-1). Export re-applies it idempotently before replaying mask patches -- the T3 order is set up here and completed by 03-06.
- **Review decodes the blob back** (`createImageBitmap`) instead of drawing the `ImageData`: it costs one decode and makes "what you see is what is sent" structural rather than a promise.
- **`meta.type` widening is in this plan; optional `blob` in `SendPayload` is not** -- that half lands with the text-only path in 03-04, next to its only consumer.

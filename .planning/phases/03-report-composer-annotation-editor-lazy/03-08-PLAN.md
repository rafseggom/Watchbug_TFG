## Phase Goal

**As an** end user of a web app, **I want to** compose a complete bug report or plain feedback -- capture or attach an image, annotate it, destructively mask anything sensitive, review it, and file it -- with the editor fetched on gesture and the whole widget UI in English or Spanish, **so that** the developer receives a report they can reproduce and neither the report nor its screenshot ever leaves the developer's own infrastructure.

**This plan's slice:** a backward + forward refactor of the *verification* layer, not the product. The suite has grown to 152 e2e tests / 876 assertions; this wave cuts it to ≤20 critical core user journeys, re-homes the rest into unit / integration / contract / VRT / packaging tests, stands up the minimal infrastructure for those types, and amends the R-12 "e2e-only, never unit tests" policy into a six-type taxonomy.

<objective>
Refactor the test suite to a deliberate six-type taxonomy: reduce e2e to ≤20 core user journeys, convert the rest to unit/integration, stand up VRT/contract/packaging with one real example each, and amend R-12.

R-12 ("DONT MAKE A BUNCH OF TESTS. Only make e2e... not unit tests") was a good constraint when the product was a thin tracer bullet — it kept the suite honest. It stops scaling once the product has a real composer, a real editor and a real API surface: 152 browser tests are slow, brittle, and most of them are really asserting a pure function or an HTTP route through an expensive browser. The owner has reversed the policy: from now on all six test types are on the table, each placed where it belongs, with e2e reserved for the ≤20 journeys that genuinely need a real browser.

Purpose: cut the suite without losing coverage (the conversion ledger is the proof), stand up enough infra that each new type is runnable today rather than aspirational, and make the policy change durable across the three documents that currently state "no unit tests, ever."

Output: a ≤20-journey e2e suite green on three engines, real unit + integration + contract + VRT + packaging suites, `R-19` recorded, AGENTS.md and ROADMAP rewritten, and a conversion ledger showing where every old assertion went.
</objective>

## Batch Protocol (CRITICAL — overrides any "just do it all" instinct)

> This wave executes in **small batches**: at most **10 files touched per iteration**. After each batch the executor **stops and asks for confirmation** before starting the next one. `autonomous: false` enforces this. A single big-bang change across the whole suite is explicitly out of bounds (see prohibition above). The 152 existing tests were built up over 7 plans precisely to keep every diff reviewable — this refactor must not undo that discipline.

## The six-type taxonomy (target state)

| # | Type | Lives in | Runner | What it may assert | Command |
|---|------|----------|--------|--------------------|---------|
| 1 | **Unit** | `tests/unit/` | Vitest | Pure logic in isolation: redaction regexes, size/pixel clamps, i18n resolver, schema mappers, path-only URL strip | `npm run test:unit` |
| 2 | **Integration / Functional** | `tests/integration/` | Vitest (+ Fastify inject / test DB) | API routes end-to-end without a browser: ingest validation, rate limit, idempotency, sanitisation, auth 401 | `npm run test:integration` |
| 3 | **E2E** | `e2e/` | Playwright, 3 engines | **≤20 core user journeys** — a real browser is genuinely required (CA-01, CA-02, CA-04) | `npm run verify` |
| 4 | **VRT (visual regression)** | `tests/vrt/` (Playwright screenshots) | Playwright `toHaveScreenshot` | Appearance of the flagship UI surfaces — hostile-CSS widget, composer, editor, panel | `npm run test:vrt` |
| 5 | **Contract** | `tests/contract/` | Vitest + `schema/report.schema.json` | Payloads validate against the single official schema; no drift between Zod and the emitted JSON Schema | `npm run test:contract` |
| 6 | **Environment / Packaging** | `tests/packaging/` (wraps scripts) | Node | Build artifacts, size tiers, compose file shape — the gates that already exist, run as tests | `npm run test:packaging` |

**Placement rule ("tests con cabeza"):** a test belongs in the cheapest layer that can still fail for the right reason. Only promote to e2e when the behaviour *requires* a real browser (shadow DOM, canvas pixels, capture API, hostile CSS) or is a cross-cutting core journey. `check:size`/`check:compose` remain hard gates regardless of how they're invoked.

**VRT rule:** a VRT baseline is only justified where the *appearance itself* is the regression surface (J-05, J-06, J-07, J-12, J-14, J-17, plus J-02's terminal screens). VRT never substitutes for CA-02's decoded-bytes assertion, and never covers deviceScaleFactor-variable rows (J-08) or simulated-network states (J-10).

**Move out of e2e → other types (from research, the "migrar a integración" bucket):** rate limiting (key/IP/day + XFF forging), server idempotency replay, layered size caps, image control stack (SVG/polyglot/decode-bomb/traversal names), write-side sanitisation, origin allowlist + project-key rejection, static/config checks (CSP, compose shape, `dangerouslySetInnerHTML` grep, size gate). These are HTTP/static-surface assertions with no user in the middle — they become integration/contract/packaging tests.

## Flagged assumptions & planner decisions (surfaced, not silent)

- **`requirements: []` is deliberate.** This wave delivers no new v1 REQ — it refactors *how* existing REQs are verified. Leaving it empty prevents double-mapping a requirement to two phases (the roadmap asserts 70/70 one-to-one coverage).

- **R-12 is amended, not deleted.** Its artifact-level security rule (CA-02 proven on encoded bytes) and its refusal to let coverage % become a vanity metric both survive in R-19. Only the "never unit tests" absolute is replaced.
- **The security rows stay e2e.** CA-02/PRV decoded-bytes and the hostile-CSS CA-04 journey are exactly the assertions that need a real browser; converting them would weaken the project's strongest evidence (T-03-32).
- **`vitest` is the only dependency this wave adds.** A devDependency, zero runtime deps (PRF-04 untouched), one exact pin.
- **VRT runs separately from `verify`.** A pixel baseline diff should never block a functional release run by accident; it is a test type, not part of the CA gate.
- **Confidence: low / batches carry the risk.** The per-test disposition (kept vs converted vs redundant) is decided *during* execution against the real rows, which is exactly why the plan mandates ≤10-file batches with confirmation — the classification is judgment work the owner reviews at each checkpoint.

Fixed decisions and analysis conclusions this plan implements (do not reopen):
1. **SEC-05 pass 2 stands**: the panel has zero HTML sinks today (`dangerouslySetInnerHTML|innerHTML|href=` = 0 occurrences in `apps/panel/src`). The CSP is defence in depth; this plan must not claim it closes an existing XSS.
2. **nginx `add_header` inheritance trap — resolved as: CSP inside `location /`, and the `X-Content-Type-Options` + `Referrer-Policy` pair repeated verbatim inside that block.** A level that declares its own `add_header` inherits NONE from the enclosing level, so a bare CSP line would silently strip both headers from every SPA response. The server-level pair stays for `location /api/`, which declares no `add_header` and therefore keeps inheriting both. Declaring the CSP at server level was rejected: it would attach a SECOND `Content-Security-Policy` header to every proxied API response alongside the blob route's own `default-src 'none'; sandbox` (`apps/api/src/routes/incidents.ts:414`) — the config already fights exactly that duplication (`proxy_hide_header X-Content-Type-Options`, lines 30-34) — and a document policy on JSON responses buys nothing.
3. **R-08 choice: `.transform()`, not `.refine()` rejection.** R-08's own wording is *stripped on ingest* (a normalisation), INFORME §4.1-6 explicitly recommends `.transform()` inside the schema so SDK and ingest inherit the rule from the single contract, and rejection would turn a future Phase-2 host sending `location.href` into a 400 instead of a silent strip. The transform is idempotent, so re-validation at both ingest stages stays safe.
4. **Emitter must pass `io: 'input'`** (probe-verified against the installed zod 4.6.5): default output mode throws `Transforms cannot be represented in JSON Schema` once the schema contains a transform; input mode emits the wire shape and is byte-identical to the committed artifact apart from the `url` description this plan adds.

The e2e row below re-proves this on every run.
6. **R-12**: e2e + property assertions only — no unit tests are created or allowed. **No new dependencies.** `schema/report.schema.json` is regenerated by script only, never hand-written.
